# 인격 경험 기록(기억) 설계

인격 성장 기능의 첫 서브 프로젝트다. 전체 순서는 1 경험 기록(이 문서) → 4 컨디션 → 2 관계 수치 → 3 성격 변경 제안·승인이며, 각각 spec → plan → 구현을 따로 거친다. 기존 인격 설계는 `2026-11-05-persona-design.md`를 따른다.

## 1. 목적

인격이 사용자와 함께한 일 중 인상 깊은 것을 근거와 함께 쌓고, 다음 대화에서 기억으로 꺼낸다. 지금은 성격이 인격 파일에 고정되어 있고 기분은 감쇠해 평온으로 돌아오므로 경험이 남지 않는다. 이 기록은 뒤 서브 프로젝트(관계 수치, 성격 변경 제안)의 근거가 된다.

### 성공 기준

- `--persona` 없이 실행하면 지금과 동작이 하나도 다르지 않다. 기억 파일이 없는 인격도 지금과 같은 시스템 append로 시작한다.
- 비정상 종료, 아주 긴 세션, compact하며 계속 쓰는 세션에서도 대화 구간이 빠짐없이 한 번씩 기록 대상이 된다.
- 다음 세션에서 인격이 지난 일을 자연스럽게 언급하고, 관련 있는 입력에 기억을 떠올린다. 떠올린 기억이 기분을 조금 움직인다.
- 기록은 대화를 막지 않고, 기록기 고장이 대화를 멈추지 않는다.

### 결정 사항 요약

| 항목 | 결정 | 이유 |
|---|---|---|
| 적용 범위 | `--persona`로 켜는 모든 인격, 인격마다 따로 | 원작 캐릭터도 사용자와의 기억은 쌓을 수 있다. 성격 변경은 3번에서 승인을 거친다 |
| 기록 주체 | Haiku가 대화 구간을 보고 0~3개 고름 | 무슨 일이 있었는지(대화 내용)를 알아야 기억다운 기록이 된다 |
| 기록 단위 | 세션 전체가 아니라 커서 이후의 대화 구간 | 세션 끝 한 번 기록은 비정상 종료·긴 세션·compact로 계속 쓰는 세션을 놓친다 |
| 구간 읽기 | SDK 세션 기록(`getSessionMessages`)에서 읽음(접근 A) | 모든 기록 시점이 한 경로를 쓰고, 비정상 종료 복구가 자연스럽고, 대화 원문을 따로 저장하지 않는다. `sessionHistory.ts`의 거르기 코드를 다시 쓴다 |
| 기억 사용 | 세션 시작 때 시스템 append에 몇 개 + 턴별 회상 | 시작 주입은 prompt cache를 유지하고, 회상은 때에 맞는 언급을 만든다 |
| 사용자에게 보이기 | 보이지 않음. 알림·목록·삭제 명령 없음 | 인격의 일기는 비밀. 틀린 기억은 3번에서 근거로 보일 때 걸러진다 |
| 인격 파일 형식 | 바꾸지 않음 | persona-lab `render-persona`·`--validate-persona`와의 계약을 지킨다 |

## 2. 구조

| 파일 | 책임 | I/O |
|---|---|---|
| `src/persona/memory/experience.ts` | `Experience`·`MemoryFile` 타입과 검증, 개수 정리, 시작용 선택, 턴별 회상 선택, 회상 기분 이벤트 계산 | 없음 |
| `src/persona/memory/segment.ts` | `SessionMessage[]` + 커서 → 기록할 구간(텍스트 줄), 앞 구간 맥락, 길이 제한 | 없음 |
| `src/persona/memory/recorder.ts` | 기록 요청 대기열, 구간 읽기 → Haiku 호출 → 경험 추가·커서 이동·저장, 실패 횟수 | SDK·파일(주입) |
| `src/persona/memory/memoryStore.ts` | `<이름>.memories.json` 읽기·쓰기(임시 파일 + rename, 저장 직전 다시 읽어 합치기), 깨진 파일 `.broken` | 파일 |

고치는 곳:

- `src/sessionHistory.ts`: 메시지 거르기 함수(`isVisible`, `userText` 등)를 export해 `segment.ts`와 함께 쓴다. 이전 대화 표시 동작은 바뀌지 않는다.
- `src/persona/mood.ts`·`tuning.ts`: `recall` 이벤트 추가.
- `src/persona/runtime.ts`: `PreCompact`·`SessionEnd` 훅 추가, `Stop`에서 세션별 턴 수 세기, `UserPromptSubmit`에서 회상과 회상 이벤트 적용. 기록은 기분 갱신 대기열과 따로 돌아 대화와 기분 처리를 막지 않는다.
- `src/persona/prompt.ts`: 시스템 append의 "기억" 단락, 턴별 상태 블록의 회상 줄.
- `src/persona/bootstrap.ts`: 기억 파일 읽기, 시작용 기억 선택, 시작 따라잡기를 백그라운드로 시작.
- `src/main.ts`: 기록기의 SDK 호출·세션 기록 읽기·비용 기록을 묶어 넘긴다(`/persona-create`와 같은 방식).

## 3. 데이터

### 3.1 기억 파일 (`<configDir>/personas/<이름>.memories.json`)

```json
{
  "version": 1,
  "experiences": [
    {
      "id": "2026-11-19T06:41:00.000Z-0",
      "summary": "/compact 명령을 만들고 main에 합치려는데 그사이 main이 바뀌어 있었다",
      "feeling": "…겹치는 파일이 없어서 다행이었어요. 진짜로요.",
      "importance": 2,
      "at": "2026-11-19T06:41:00.000Z",
      "sessionId": "85d514c8-9479-48bc-b83b-983a0b7d9380",
      "moodReasons": ["테스트 통과", "도구 실패"],
      "moodDelta": { "stress": 4, "dopamine": 6 }
    }
  ],
  "sessions": [
    {
      "sessionId": "85d514c8-9479-48bc-b83b-983a0b7d9380",
      "cwd": "/Users/bran/personal/claud3",
      "cursor": "메시지 uuid 또는 null",
      "failures": 0,
      "lastSeenAt": "2026-11-19T07:02:00.000Z",
      "lastReadAt": "2026-11-19T07:02:00.000Z"
    }
  ]
}
```

- `experiences`: 최대 300개. `summary` 120자, `feeling` 60자 이내(넘으면 자른다). `importance`는 1~3 정수. `id`는 기록 시각 + 그 기록 안의 순번.
- `moodReasons`: 구간 시간대(구간 첫 메시지 ~ 마지막 메시지)에 있었던 기분 변동 이유 문구. `MoodState.recentReasons`(최근 10개)에서 고르므로, 시간이 지난 따라잡기 기록에서는 비어 있을 수 있다. 비어 있으면 `moodDelta`는 0이고 회상 이벤트가 생기지 않는다.
- `moodDelta`: 같은 이유들의 stress·dopamine 변화 합계. 회상 이벤트의 방향을 정한다.
- `sessions`: 이 인격이 켜졌던 세션. 최근 `lastSeenAt` 순 20개까지. `cursor`는 마지막으로 기록에 넣은 메시지 uuid(처음 `null`). `failures`는 현재 구간의 연속 실패 횟수. `lastReadAt`은 세션 기록을 마지막으로 읽은 시각.
- 파일이 없으면 빈 목록으로 시작한다. 기분 파일과 따로 두어 저장 주기와 손상 범위를 나눈다.
- 세션별 턴 수는 파일에 저장하지 않는다(재시작 후 0부터 세도 따라잡기가 남은 구간을 처리한다).

### 3.2 수치 (`tuning.ts`)

| 상수 | 값 | 뜻 |
|---|---|---|
| `MEMORY_LIMIT` | 300 | 경험 최대 개수 |
| `MEMORY_SESSION_LIMIT` | 20 | 추적하는 세션 수 |
| `RECORD_EVERY_TURNS` | 10 | 이 턴 수마다 기록 요청 |
| `STARTUP_MEMORIES` | 6 | 시스템 append에 넣는 기억 수 |
| `RECALL_SIMILARITY` | 0.35 | 회상 기준 bigram 유사도(써 보며 조정) |
| `RECALL_MAX` | 2 | 한 턴에 떠올리는 최대 개수 |
| `RECALL_COOLDOWN_TURNS` | 10 | 같은 기억을 다시 떠올리지 않는 턴 수 |
| `RECALL_DELTAS` | 1: 3, 2: 5, 3: 8 | 회상 이벤트 크기(중요도별) |
| `RECORD_TIMEOUT_MS` | 60,000 | Haiku 호출 시간 제한 |
| `RECORD_BUDGET_USD` | 0.05 | 호출당 `maxBudgetUsd` |
| `RECORD_MAX_FAILURES` | 3 | 같은 구간 연속 실패 시 포기 |
| `PRECOMPACT_WAIT_MS` | 20,000 | `PreCompact`에서 기록을 기다리는 최대 시간(5장 확인 결과에 따라 0일 수 있음) |
| `SESSION_STALE_DAYS` | 30 | 이 기간 넘게 읽지 못한 세션은 목록에서 뺀다 |
| 구간 길이 | 사용자 입력 1,000자, 응답 400자, 전체 24,000자 | 넘으면 메시지별로 자르고, 전체는 오래된 앞부분부터 버린다 |

## 4. 흐름

### 4.1 세션 등록

훅이 처음 보는 `session_id`로 불리면 `sessions`에 `cursor: null`, 현재 `cwd`로 추가한다. `/clear`·`/resume`으로 세션이 바뀌면 훅 입력의 `session_id`가 바뀌므로 따로 처리하지 않는다.

### 4.2 기록 (`recorder`)

1. 요청은 `(sessionId, 이유)`. 같은 세션의 요청이 대기 중이면 합친다. 기록은 한 번에 하나만 돈다.
2. `getSessionMessages(sessionId, { dir: cwd })`로 메시지를 읽고 `lastReadAt`을 갱신한다.
3. `segment`가 커서 다음부터 끝까지를 구간으로 자른다(커서가 `null`이면 처음부터). 커서 메시지가 목록에 없으면 마지막 compact 요약 다음부터로 본다(5장 확인 결과로 확정).
4. 구간에 사용자 입력이 없으면 호출하지 않고 끝낸다(커서도 그대로).
5. Haiku를 `runStructuredQuery`로 부른다(도구 없음, `settingSources: []`, `outputFormat` JSON schema, `maxTurns` 1, `maxBudgetUsd` 0.05, 60초 제한).
6. 성공하면 경험을 추가하고 개수를 정리한 뒤, 커서를 구간 마지막 메시지로 옮기고 `failures`를 0으로 해서 한 번에 저장한다. 고른 경험이 0개여도 커서는 옮긴다.
7. 비용은 사용량 기록에 합산한다.

### 4.3 기록 시점

| 시점 | 동작 |
|---|---|
| `Stop` | 그 세션의 턴 수를 올리고, 10이 되면 기록 요청 후 0으로. 기다리지 않는다 |
| `PreCompact` | 기록 요청 후 `PRECOMPACT_WAIT_MS`까지 기다린다. 압축 후에도 세션 기록에 원문이 남으면 기다리지 않는다(5장) |
| `SessionEnd` | 기록 요청. 기다리지 않는다. 종료로 끊기면 다음 시작 때 따라잡는다 |
| 시작 | `sessions` 중 커서 뒤에 메시지가 남은 세션을 차례로 백그라운드 기록. `SESSION_STALE_DAYS` 넘게 못 읽은 세션은 목록에서 뺀다 |

### 4.4 Haiku 입력·출력

입력:

- 인격 소개: 이름, 요약, 관계, 말투 예시, 말버릇.
- 선정 기준과 중요도 표(4.5).
- 최근 경험 20개의 `summary`(같은 종류를 다시 고르지 않게).
- 구간 시간대의 기분 변동 이유. 극단 진입·탈출이나 부호 전환이 있었으면 "강한 후보" 표시.
- 앞 구간의 마지막 사용자 입력·응답 2쌍(맥락 참고용, 기록 대상 아님).
- 구간 대화: 사용자 입력과 응답 텍스트, 도구는 `⏺ 이름 (성공|실패)`만. 도구 출력 본문은 넣지 않는다.

출력(`outputFormat`): `{ "experiences": [{ "summary": string, "feeling": string, "importance": 1|2|3 }] }`, 0~3개. 빈 배열이 정상 결과다. `feeling`은 인격의 말투로 쓴 한 줄 소감.

### 4.5 선정 기준과 중요도

들어가는 것:

- 감정이 크게 움직인 순간(극단 진입·탈출, 큰 변동)
- 처음 있는 일
- 사용자와의 관계가 드러난 일(칭찬, 꾸중, 농담, 부탁)
- 막혔다가 넘긴 일
- 인격의 실수
- 대화 흐름이 크게 바뀐 일(작업하다 잡담으로 샌 일, 계획을 엎은 일)

들어가지 않는 것: 평범한 성공·반복 작업, 이미 기억에 있는 것과 같은 종류의 일, 작업 내용 자체(코드 세부사항).

기본값은 0개다. 기준에 분명히 해당할 때만 고른다(평소 10턴에 0~1개 예상). 고른 것과 점수는 같은 기준으로 한 번에 판단하며, 코드는 점수를 덮어쓰지 않는다.

| 중요도 | 뜻 | 예 |
|---|---|---|
| 3 | 기준에 강하게 해당, 오래 기억할 일 | 극단 진입·탈출, 진지한 칭찬·꾸중, 처음 겪은 큰 일 |
| 2 | 기준에 분명히 해당 | 막혔다가 넘긴 일, 인격의 실수, 가벼운 농담·부탁, 큰 흐름 전환 |
| 1 | 기준에 걸치지만 약함 | 기분이 조금 움직인 평범한 일 |

### 4.6 개수 정리

300개를 넘으면 중요도가 낮은 것부터, 같은 중요도면 오래된 것부터 지운다.

### 4.7 기억 꺼내기

시작(시스템 append, 세션 1회):

- 중요도 내림차순, 같은 중요도면 최근 순으로 6개를 고른다.
- 단락 형식:

  ```
  ## 기억
  사용자와 함께한 일 중 기억나는 것. 대화에 자연스러울 때만 꺼내고, 억지로 언급하지 않는다.
  - 11/19 /compact 명령을 만들고 main에 합치려는데 그사이 main이 바뀌어 있었다 (…겹치는 파일이 없어서 다행이었어요. 진짜로요.)
  ```

- 가장 최근 세션의 중요도 3 기억이 있으면 "첫 대화에서 이 일을 먼저 언급해도 된다(한 번만)"를 덧붙인다.
- 기억이 없으면 단락을 넣지 않는다. 세션 중에 새로 기록된 경험은 append에 넣지 않는다(캐시 유지).

턴별 회상(`UserPromptSubmit`, 사용자 입력일 때만):

- 정규화한 입력과 각 경험 `summary`의 `bigramSimilarity`가 `RECALL_SIMILARITY` 이상인 것 중 유사도 순 최대 2개.
- 시스템 append에 들어간 것과 최근 10턴 안에 떠올린 것은 뺀다. 세션 중 새로 기록된 경험도 대상이다.
- 상태 블록에 `떠오른 기억: 11/19 …` 줄을 붙인다.
- 중요도 3이면 "강하게 떠오름 — 하던 얘기를 멈추고 먼저 꺼내도 된다"를 붙인다. 이 문구는 세션당 한 번만.

### 4.8 회상 기분 이벤트

새 기분 이벤트 `{ kind: "recall", experienceId, importance, moodDelta }`. 떠올린 기억마다 하나씩 적용한다.

- 크기: `RECALL_DELTAS[importance]`.
- 방향: `moodDelta.stress`·`moodDelta.dopamine` 각각의 부호(0이면 그 축은 변화 없음).
- 민감도 배율·커플링 등 기존 보정을 다른 이벤트처럼 적용한다.
- 변동 이유 문구: `기억: <summary 앞 20자>…`.

## 5. 확인할 것 (plan 첫 단계)

실제 SDK로 확인하고 `docs/suberpowers/notes/`에 결과를 남긴 뒤 아래 규칙을 확정한다.

1. 세션 진행 중에도 `getSessionMessages`가 방금 끝난 턴까지 돌려주는가. 아니면 접근 A를 다시 검토한다.
2. compact 후 `getSessionMessages`가 압축 전 메시지를 돌려주는가.
   - 돌려주면: `PRECOMPACT_WAIT_MS`는 0(기다리지 않음), 커서는 항상 찾을 수 있다.
   - 안 돌려주면: `PreCompact`에서 기다리고, 커서를 못 찾으면 마지막 compact 요약 다음부터 본다.
3. `SessionEnd` 훅이 `/clear`·`/resume`·종료에서 각각 불리는가.

## 6. 에러 처리

| 상황 | 처리 |
|---|---|
| Haiku 실패·시간 초과·형식 오류 | 저장하지 않고 커서 유지, `failures` +1. 다음 기록 때 그 구간을 포함해 다시 |
| 같은 구간 3번 연속 실패 | 커서를 구간 끝으로 넘기고 포기(비용 폭주 방지) |
| `getSessionMessages` 실패 | 이번 기록만 건너뜀. 30일 넘게 못 읽은 세션은 시작 때 목록에서 뺀다 |
| 기억 파일 깨짐 | `.broken`으로 옮기고 빈 상태로 시작 |
| 기록 도중 종료 | 경험 추가와 커서 이동을 한 번의 파일 쓰기(임시 파일 + rename)로 묶어 중복 기록이 없다 |
| 같은 인격으로 claud3 두 개 동시 실행 | 저장 직전에 파일을 다시 읽어 합친다. 경험은 `id` 기준 합집합, 세션은 `sessionId` 기준으로 커서가 더 뒤인 쪽 |
| 기록기 예외 | 삼켜서 대화를 막지 않는다. 경고는 실행당 한 번만 흐린 글씨로(기억 내용은 보이지 않는다) |
| 비용 | 호출당 `maxBudgetUsd` 0.05 |

## 7. 테스트

실제 API를 호출하지 않는다. `queryFn`과 세션 기록 읽기 함수, 파일 디렉터리(`CLAUD3_CONFIG_DIR` 또는 인자)를 주입한다.

| 대상 | 확인할 것 |
|---|---|
| `experience.ts` | 검증(길이 자르기, 중요도 범위, 깨진 항목 버림), 정리 순서, 시작용 6개 순위, 회상(기준, 최대 2개, append 제외, 10턴 쿨다운), 회상 이벤트의 방향·크기 |
| `segment.ts` | 커서 다음부터 자르기, 커서 없음(`null`) → 처음부터, 커서 못 찾음 → 마지막 compact 요약 다음부터, 서브에이전트·메타·명령 기록 제외, 도구 이름·성패만, 길이 제한, 앞 구간 2쌍 맥락, 사용자 입력 없으면 빈 구간 |
| `recorder.ts` | 같은 세션 요청 합치기, 한 번에 하나, 성공 시 경험 추가·커서 이동, 0개여도 커서 이동, 실패 시 커서 유지, 3번 연속 실패면 포기, 빈 구간은 호출 안 함, 비용 콜백, 프롬프트에 강한 후보·최근 20개 요약 포함 |
| `memoryStore.ts` | 읽기·쓰기, 없는 파일, 깨진 파일 `.broken`, 저장 직전 합치기, 원자적 쓰기 |
| `runtime.ts` | 새 `session_id` 등록, `Stop` 10번째에 기록 요청, `PreCompact` 대기·시간 제한, `SessionEnd` 비대기, 회상 이벤트 적용과 이유 문구, 기록기 예외가 훅 결과에 영향 없음, 경고 한 번 |
| `prompt.ts` | "기억" 단락(없으면 없음), 먼저 언급 문구, 회상 줄, 강하게 떠오름 문구 세션당 한 번 |
| `bootstrap.ts` | 따라잡기 대상(커서 뒤 메시지가 남은 세션만), 오래된 세션 정리 |
| 회귀 | `--persona` 없이 동작 동일, 기억 파일 없으면 기존 append와 동일, `sessionHistory`의 이전 대화 표시 동일 |

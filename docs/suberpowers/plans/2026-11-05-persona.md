# 인격(persona) Implementation Plan

> **agentic worker에게:** REQUIRED SUB-SKILL: 이 plan을 task 단위로 구현하려면 suberpower:subagent-driven-development(권장) 또는 suberpower:executing-plans를 사용하세요. Step은 추적을 위해 checkbox(`- [ ]`) 문법을 사용합니다.

**Goal:** `claud3 --persona <이름>`으로 스트레스·도파민 상태를 가진 캐릭터와 대화하고, `/persona-create <이름>`으로 인격을 만든다.

**Architecture:** `src/persona/`에 순수 모듈(수치·판정·프롬프트)과 조립 모듈(store·runtime·create)을 둔다. 런타임은 SDK `hooks` 콜백과 `systemPrompt.append`로 `query()`에 붙고, 화면은 런타임을 구독해 캐릭터 패널을 그린다. 조사·생성·반응 판단은 도구를 제한한 별도 one-shot `query()`다.

**Tech Stack:** TypeScript(ESM, Node ≥ 24), `@anthropic-ai/claude-agent-sdk` ^0.3.306, Ink 8, vitest, ink-testing-library

**Spec:** `docs/suberpowers/specs/2026-11-05-persona-design.md`

## Global Constraints

- 브랜치 `feat/persona`(e042ab9 기준). `repro-loop.tsx`는 건드리지도 commit하지도 않는다.
- TDD: 테스트를 먼저 쓰고 실패를 확인한 뒤 구현한다. `any` 금지(`unknown`에서 좁힌다).
- 자동 테스트에서 실제 API·네트워크·`sysctl`을 호출하지 않는다. `queryFn`·시계·명령 실행을 주입한다.
- API 키를 출력·저장하지 않는다. one-shot `query()`에도 `env`로만 넘긴다.
- 사용자에게 보이는 문구는 한국어.
- 모든 수치 상수는 `src/persona/tuning.ts`에만 둔다(spec 4장 값 그대로).
- `--persona`가 없으면 `buildBaseOptions` 결과와 기존 동작이 이전과 같다.
- 저장 경로: `<configDir()>/personas/<이름>.json`, `<이름>.mood.json`. `configDir()`은 `src/usageStore.ts`의 것을 쓴다.
- 인격 이름: `^[a-z0-9_-]{1,32}$`.
- 반응 판단 모델: `claude-haiku-5-5`. 조사: `tools: ["WebSearch", "WebFetch"]`, `maxTurns: 15`, `maxBudgetUsd: 0.5`. 모든 one-shot은 `settingSources: []`.
- 각 task가 끝날 때 `npm test`와 `npm run typecheck`가 모두 통과해야 commit한다.
- commit 메시지 끝에 `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.

## Review Focus

1. 여러 도구가 병렬로 끝나 `PostToolUse` hook이 동시에 들어올 때 — 기분 갱신이 유실되지 않고 순서대로 반영·저장되어야 한다(Task 7에 테스트).
2. 줄 전체가 괄호지만 코드 블록 안이거나 함수 호출처럼 생긴 줄(`(a, b) => a + b`는 괄호로 끝나지 않지만 `(foo())`는 끝남) — 코드 블록 안은 행동으로 보지 않는다. 코드 블록 밖의 `(foo())`는 행동으로 본다(Task 5에 두 경우 테스트).
3. 기분 파일의 `updatedAt`이 미래 시각(시계 변경)이거나 파싱 불가 — 감쇠가 음수 경과로 수치를 키우지 않아야 한다(경과 0으로 처리, Task 2에 테스트).
4. `--persona`와 `--resume`을 함께 쓸 때 — 시스템 append와 hooks가 재개한 세션에도 붙어야 한다(Task 8에 테스트).
5. `/persona-create` 진행 중 턴이 실행 중이거나 질문을 취소할 때 — 턴 중이면 시작하지 않고(`BUSY_MESSAGE`), 질문 취소 시 파일을 만들지 않는다(Task 11에 테스트).

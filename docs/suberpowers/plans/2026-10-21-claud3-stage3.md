# claud3 3단계(Ink TUI) Implementation Plan

> **agentic worker에게:** REQUIRED SUB-SKILL: 이 plan을 task 단위로 구현하려면 suberpower:subagent-driven-development(권장) 또는 suberpower:executing-plans를 사용하세요. Step은 추적을 위해 checkbox(`- [ ]`) 문법을 사용합니다.

> **갱신 2026-10-22:** 2단계 이후 추가된 권한 모드 기능(`permission_mode` 이벤트, 상태 줄 모드, Shift+Tab 순환, `/mode`, 계획 승인 y/e/n, `allowAcceptEdits`)과 2단계 입력 기록을 반영했다. 화면 공용 부분 분리(Task 1)를 새로 넣었다.

**Goal:** 같은 `Session`과 `UiEvent`를 쓰는 Ink 화면을 기본 UI로 추가하고, `--plain`으로 기존 readline 화면을 유지한다. 사용자가 할 수 있는 일(명령, 키, 권한·계획 질문, 입력 기록)은 두 화면이 같다.

**Architecture:** 화면 상태는 순수 함수 `reduceTranscript(state, event)`가 `UiEvent`로부터 만든다. Ink 컴포넌트(`App`, `Transcript`, `InputBox`, `PermissionDialog`, `StatusBar`)는 그 상태를 그리기만 한다. 권한 요청은 `PermissionPrompter`가 대기열에 넣고, `PermissionDialog`의 선택으로 resolve한다. 2단계의 `commands`·`usageStore`·`MultilineBuffer`·`formatStatusLine`과 권한 모드의 `permissionModes`·`parseDecision`·`parsePlanDecision`은 그대로 재사용한다. 명령 출력(`print`)과 입력 기록 저장은 화면마다 다르므로 Task 1에서 화면 쪽으로 옮긴다.

**Tech Stack:** 기존 + `ink`(작성 시점 8.0.0, Node ≥22), `react`(19.3.x, ink peer `>=19.3.0`), `@types/react`, `ink-testing-library`(4.0.0). 설치 후 `render`(`exitOnCtrlC` 옵션), `Static`, `useInput`(`key.tab`·`key.shift`·`key.escape`·`key.ctrl`), `useStdout`, `Box`, `Text` API를 context7 문서로 확인한다.

**Spec:** `docs/suberpowers/specs/2026-10-21-claud3-design.md` (6절 3단계, 권한 모드)

## Global Constraints

- 1·2단계와 권한 모드 계획의 Global Constraints를 따른다(TDD, `any` 금지, 실제 API는 자동 테스트에서 호출하지 않음, 사용자 문구는 한국어).
- `tsconfig.json`에 `"jsx": "react-jsx"`를 추가하고 컴포넌트는 `src/ui/ink/*.tsx`에 둔다. `module: NodeNext`이므로 `.tsx` 파일도 `./App.js`처럼 `.js` 확장자로 import한다.
- `--plain`이면 `ui/plain`, 아니면 Ink UI. stdin이 TTY가 아니면 자동으로 `ui/plain`.
- 완료된 대화 항목은 Ink `Static`으로 그려 스크롤 성능을 유지한다. 진행 중인 응답·실행 중인 도구·대화상자·입력창·상태 줄만 동적으로 그린다.
- 키는 `ui/plain`과 같다: Esc(실행 중 턴 중단), Ctrl+C(질문 중이면 거부+중단, 여러 줄 입력 중이면 취소, 실행 중이면 중단, 대기 중이면 2초 안에 두 번 눌러 종료), Ctrl+D(종료), Shift+Tab(권한 모드 순환, 질문 중에는 무시), ↑/↓(입력 기록). Ink `render`는 `exitOnCtrlC: false`로 부른다.
- 사용자에게 보이는 문구(권한 모드 줄, 종료 시 세션 ID, 크레딧 안내, 중단 표시, 종료 확인)는 `ui/plain`과 같은 문장을 쓴다.

## Review Focus

1. 터미널 폭이 매우 좁음(40칸) → 줄바꿈되어도 깨지지 않고 상태 줄이 한 줄을 넘으면 잘린다.
2. 응답 스트리밍 중 권한 요청 → 진행 중 텍스트를 확정(Static으로 이동)한 뒤 대화상자를 띄운다.
3. 권한 대화상자에서 Esc → 거부(deny). Ctrl+C → 거부하고 턴 중단. SDK가 요청을 취소(`signal` abort) → 대화상자를 닫고 deny.
4. 권한 요청이 동시에 두 개 → 하나씩 차례로 묻는다.
5. 매우 긴 단일 응답(수천 줄)이나 긴 계획 본문 → 입력창·대화상자가 화면 밖으로 밀려나지 않는다(계획 본문은 대화 영역에 확정 출력하고 대화상자에는 질문만 둔다).
6. 한국어 등 전각 문자 입력·커서 이동 → 입력창 표시 폭이 어긋나지 않는다.
7. 턴 실행 중 Shift+Tab → 모드가 바뀌고 상태 줄이 즉시 갱신된다. 변경 실패 → 오류 notice, 상태 줄은 이전 모드.
8. 대화상자가 떠 있는 동안 입력창 키 입력이 섞이지 않는다.

### Task 2: 대화 상태 리듀서 (`ui/ink/transcript.ts`)

**Files:** Create `src/ui/ink/transcript.ts`, Test `test/ink-transcript.test.ts`

**Interfaces:**
- Consumes: `UiEvent`, `describePermissionMode`
- Produces:
  ```ts
  export type TranscriptItem =
    | { kind: "user"; id: number; text: string }
    | { kind: "assistant"; id: number; text: string }
    | { kind: "tool"; id: number; toolUseId: string; name: string; summary: string; input: Record<string, unknown>; status: "running" | "done" | "error"; errorSummary?: string }
    | { kind: "notice"; id: number; tone: "info" | "error" | "dim"; text: string };
  export interface TranscriptState {
    done: TranscriptItem[];                                  // Static으로 그리는 확정 항목
    running: (TranscriptItem & { kind: "tool" })[];          // 실행 중인 도구
    streaming?: TranscriptItem & { kind: "assistant" };      // 진행 중인 응답
    nextId: number;
    sessionCostUsd: number;
    model?: string;
    permissionMode?: PermissionMode;
    header?: string;
  }
  export const initialTranscript: TranscriptState;
  export function addUserInput(state: TranscriptState, text: string): TranscriptState;
  export function addNotice(state: TranscriptState, tone: "info" | "error" | "dim", text: string): TranscriptState;
  /** 진행 중 응답을 done으로 확정한다. 권한·계획 질문을 띄우기 직전에 부른다. */
  export function commitStreaming(state: TranscriptState): TranscriptState;
  export function reduceTranscript(state: TranscriptState, event: UiEvent): TranscriptState;
  ```
- 규칙:
  - `text_delta`는 `streaming`에 이어 붙인다. 그 밖의 모든 이벤트는 먼저 `streaming`을 `done`으로 확정한다.
  - `tool_start`는 `running`에 추가한다. `tool_end`는 같은 `toolUseId` 항목의 status를 바꿔 `running`에서 `done`으로 옮긴다(Static에 들어간 항목은 다시 그려지지 않기 때문).
  - `turn_result`는 `sessionCostUsd = totalCostUsd`. 오류면 error notice를 넣고, 메시지가 `credit balance`를 포함하면 크레딧 안내 notice를 하나 더 넣는다(`ui/plain`의 `CREDIT_HINT`를 export해 재사용). 이어서 `── $턴 · 누적 $합계` dim notice.
  - `session_start`는 `header`·`model`을 설정한다.
  - `permission_mode`는 `permissionMode`를 설정하고 `권한 모드: <describePermissionMode>` dim notice를 넣는다.
  - `error`는 `오류: <메시지>` error notice.
  - `session_closed`는 세션 ID(있으면 `세션 ID: <id>  (이어서: claud3 --resume <id>)`)와 `누적 비용 $…` info notice.

### Task 3: Ink 컴포넌트

**Files:** Create `src/ui/ink/App.tsx`, `Transcript.tsx`, `InputBox.tsx`, `PermissionDialog.tsx`, `StatusBar.tsx`, `index.tsx`, Test `test/ink-components.test.tsx`; Modify `tsconfig.json`, `vitest.config.ts`(`test/**/*.test.{ts,tsx}`), `package.json`

**Interfaces:**
- Consumes: Task 1·2, `parseInput`·`runCommand`, `MultilineBuffer`·`formatStatusLine`·`parseDecision`·`parsePlanDecision`·`formatPlanPreview`, `formatToolDiff`(tool 항목 아래 diff), `createMarkdownRenderer`(assistant 텍스트), `nextPermissionMode`, `remainingCreditUsd`
- Produces:
  - `export function createInkUi(options: { stdin?: NodeJS.ReadStream; stdout?: NodeJS.WriteStream; historyFile?: string }): ChatUi`
  - `PermissionDialog`는 두 종류다.
    - 도구: 제목 `<도구>(<요약>) 허용할까요?`, 선택지 `이번만 허용`(y) · `세션 동안 항상 허용`(a) · `거부`(n)
    - 계획(`request.plan`이 있음): 계획 본문(`formatPlanPreview`)은 열기 직전 대화 영역에 notice로 확정 출력하고, 대화상자는 `계획을 승인할까요?`와 선택지 `승인`(y → `allow`) · `승인+편집 자동 허용`(e → `allowAcceptEdits`) · `계속 계획`(n → `deny`)
    - 공통: ↑/↓·Enter 또는 단축키로 고른다. Esc는 deny, Ctrl+C는 deny와 `session.interrupt()`, `signal` abort면 닫고 deny.
  - prompter: 요청을 대기열에 넣고 하나씩 대화상자로 보여 준다. 열기 직전에 `commitStreaming`.
  - `InputBox`: `> ` 프롬프트, 줄 끝 `\` + Enter는 `… ` 프롬프트로 이어 받기(`MultilineBuffer`), ↑/↓ 입력 기록(`loadHistory`로 시작, 보낼 때 `createHistorySaver`로 저장, 대화상자 답은 기록하지 않음), 전각 문자 폭 고려.
  - `StatusBar`: `formatStatusLine({ model, permissionMode, sessionCostUsd, remainingCreditUsd })`. 시작할 때 `commandContext.readUsage()`로 잔액을 채우고 `turn_result`마다 `recordUsage(costUsd)` 결과로 갱신한다. `recordUsage` 실패는 error notice로 보인다. 모드·모델이 바뀌면 바로 다시 그린다.
  - `App` 키: Esc(실행 중이면 `interrupt` + `(중단됨)` notice), Ctrl+C·Ctrl+D(Global Constraints대로), Shift+Tab(대화상자가 없으면 `session.setPermissionMode(nextPermissionMode(session.currentPermissionMode))`, 실패 시 error notice).
  - 명령: `runCommand`에 넘기는 `print`는 info notice를 넣는다.

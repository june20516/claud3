# claud3 2단계(편의 기능) Implementation Plan

> **agentic worker에게:** REQUIRED SUB-SKILL: 이 plan을 task 단위로 구현하려면 suberpower:subagent-driven-development(권장) 또는 suberpower:executing-plans를 사용하세요. Step은 추적을 위해 checkbox(`- [ ]`) 문법을 사용합니다.

**Goal:** 1단계 CLI에 자체 슬래시 명령, 크레딧 추정 상태 줄, 여러 줄 입력, 실행 간 입력 기록을 더한다.

**Architecture:** 입력은 `commands.parseCommand`가 먼저 보고 claud3 명령이면 `CommandContext`(Session·사용량 저장소·출력 함수)로 처리하고, 아니면 지금처럼 `session.send`로 넘긴다. 사용량은 `usageStore`가 `~/.config/claud3/usage.json`에 누적하고, 상태 줄은 `turn_result` 뒤에 `ui/plain`이 그린다. `Session`에는 모델 변경과 세션 교체 기능을 더한다.

**Tech Stack:** 1단계와 같음 (추가 의존성 없음)

**Spec:** `docs/suberpowers/specs/2026-10-21-claud3-design.md` (6절 2단계, 4절 데이터 흐름)

## Global Constraints

- 1단계 Global Constraints(`docs/suberpowers/plans/2026-10-21-claud3-stage0-1.md`)를 그대로 따른다. 특히 자동 테스트에서 실제 API 호출 금지, `any` 금지, 사용자 문구는 한국어.
- 개발 중 확인은 `npm run dev`로 한다. 전역 `claud3`(안정판)는 사용자 요청이 있을 때만 `npm run promote`로 갱신한다.
- 시작 잔액 기본값 US$100. 사용량 파일 `~/.config/claud3/usage.json`, 입력 기록 파일 `~/.config/claud3/history`(최대 500줄). 두 경로 모두 `CLAUD3_CONFIG_DIR` 환경변수로 바꿀 수 있다(테스트용).
- claud3 자체 명령: `/cost`, `/clear`, `/model <name>`, `/resume <id>`, `/help`. 그 밖의 `/`로 시작하는 입력(플러그인 스킬 `/suberpower:...` 등)은 SDK로 넘긴다.

## Review Focus

1. `usage.json`이 없거나 깨짐 → 기본값(시작 잔액 100, 사용 0)으로 시작하고, 다음 기록 때 정상 파일로 덮어쓴다.
2. 턴 실행 중 `/model`, `/clear`, `/resume` → 실행하지 않고 "턴이 끝난 뒤 다시 입력해 주세요"를 표시한다. `/cost`, `/help`는 실행 중에도 된다.
3. `/model`, `/resume`에 인자 없음 → 사용법 한 줄을 표시하고 아무것도 바꾸지 않는다.
4. 여러 줄 입력 중 Ctrl+C → 모아 둔 줄을 버리고 새 프롬프트를 띄운다.
5. 같은 프로세스에서 `claud3` 두 개가 동시에 실행되어 `usage.json`을 쓰는 경우 → 매 기록마다 파일을 다시 읽고 더해서 쓴다(마지막 쓰기만 남는 손실을 줄인다).

**Interfaces:**
- Produces:
  ```ts
  export interface UsageSnapshot { startingCreditUsd: number; spentUsd: number }
  export function configDir(): string; // CLAUD3_CONFIG_DIR ?? ~/.config/claud3
  export async function readUsage(dir?: string): Promise<UsageSnapshot>;
  export async function addUsage(costUsd: number, dir?: string): Promise<UsageSnapshot>; // 다시 읽고 더해서 씀
  export function remainingCreditUsd(snapshot: UsageSnapshot): number; // max(0, starting − spent)
  ```

- [ ] **Step 4: 통과 확인** — `npx vitest run test/usageStore.test.ts && npm run typecheck` → PASS

### Task 2: Session에 모델 변경과 세션 교체 추가

**Files:** Modify `src/session.ts`, `test/session.test.ts`

**Interfaces:**
- Consumes: 1단계 `Session`, `SessionQuery`
- Produces:
  - `SessionQuery`에 `setModel(model?: string): Promise<void>` 추가 (SDK `Query.setModel`과 같은 시그니처)
  - `Session.setModel(model: string): Promise<void>` — 현재 query에 전달하고 `currentModel`을 갱신
  - `get currentModel(): string | undefined` — `baseOptions.model`로 시작, init의 `model`로 갱신
  - `Session.replace(resume?: string): Promise<void>` — 현재 입력 대기열을 닫고, 새 query를 연다. `resume`이 없으면 새 대화(`/clear`), 있으면 그 세션으로 이동(`/resume`). 세션 비용(`totalCostUsd`)은 0으로 다시 시작. `session_closed`는 내지 않는다.
  - busy일 때 `setModel`/`replace`를 부르면 `Error("턴이 끝난 뒤 다시 입력해 주세요")`를 던진다.

- [ ] **Step 1: 실패하는 테스트** — 가짜 SDK(`FakeSdk`)에 `setModel` 기록을 추가. `setModel("x")` → 가짜 query의 `setModel("x")` 호출, `currentModel === "x"`; `replace()` → `queryFn`이 두 번째로 불리고 options에 `resume` 없음, 이후 `send`는 두 번째 query로 감, `totalCostUsd` 0; `replace("abc")` → options.resume `"abc"`, `sessionId === "abc"`; busy 중 `setModel`/`replace` → 지정 메시지로 reject; init 수신 시 `currentModel` 갱신.
- [ ] **Step 2: 실패 확인** — `npx vitest run test/session.test.ts` → 새 테스트 FAIL
- [ ] **Step 3: 구현** — 이전 query의 메시지 루프가 끝나며 연결 끊김으로 처리되지 않도록, 교체된 query의 `consume`은 자기가 현재 query가 아니면 조용히 끝낸다.
- [ ] **Step 4: 통과 확인** — `npm test && npm run typecheck` → PASS
- [ ] **Step 5: Commit** — `feat: Session 모델 변경과 세션 교체`

### Task 3: 슬래시 명령 (`commands`)

**Files:** Create `src/commands.ts`, Test `test/commands.test.ts`

**Interfaces:**
- Consumes: Task 1 `readUsage`·`remainingCreditUsd`, Task 2 `Session.setModel`·`replace`·`currentModel`
- Produces:
  ```ts
  export type ParsedInput =
    | { kind: "command"; name: "cost" | "clear" | "model" | "resume" | "help"; argument: string }
    | { kind: "prompt"; text: string };
  export function parseInput(line: string): ParsedInput; // 앞뒤 공백 제거 후 판정, 이름은 대소문자 구분
  export interface CommandContext {
    session: Pick<Session, "isBusy" | "totalCostUsd" | "currentModel" | "sessionId" | "setModel" | "replace">;
    readUsage: () => Promise<UsageSnapshot>;
    print: (text: string) => void;
  }
  export async function runCommand(command: Extract<ParsedInput, { kind: "command" }>, context: CommandContext): Promise<void>;
  ```
- 출력 문구:
  - `/cost`: `세션 $<4자리> · 전체 누적 $<spent 4자리> · 남은 크레딧 추정 $<remaining 2자리> (정확한 값은 Console)`
  - `/clear`: `새 대화를 시작했습니다`
  - `/model x`: `모델을 x(으)로 바꿨습니다`; 인자 없음: `사용법: /model <name>  (현재: <currentModel ?? 기본값>)`
  - `/resume id`: `세션 <id>(으)로 이동했습니다`; 인자 없음: `사용법: /resume <session-id>`
  - `/help`: 명령 목록과 Esc·Ctrl+C·Ctrl+D·여러 줄 입력(`\`로 끝내기) 안내
  - busy 중 `/model`·`/clear`·`/resume`: `턴이 끝난 뒤 다시 입력해 주세요`

- [ ] **Step 1: 실패하는 테스트** — `parseInput`: `/cost` → command cost; ` /model  claude-x ` → model, argument `"claude-x"`; `/suberpower:brainstorming` → prompt; `/unknown` → prompt; `hello` → prompt. `runCommand`: 위 출력 문구 각각, busy 분기, 인자 없음 분기(가짜 session으로 `setModel`/`replace` 미호출 확인).
- [ ] **Step 2: 실패 확인** — `npx vitest run test/commands.test.ts` → FAIL
- [ ] **Step 3: 구현**
- [ ] **Step 4: 통과 확인** — `npx vitest run test/commands.test.ts && npm run typecheck` → PASS
- [ ] **Step 5: Commit** — `feat: claud3 슬래시 명령`

### Task 4: 화면 연결 — 명령, 상태 줄, 여러 줄 입력, 입력 기록

**Files:** Modify `src/ui/plain.ts`, `src/main.ts`, `test/ui-plain.test.ts`

**Interfaces:**
- Consumes: Task 1, Task 3
- Produces:
  - `export function formatStatusLine(params: { model?: string; sessionCostUsd: number; remainingCreditUsd: number }): string` → `<model ?? 기본 모델> · 세션 $<4자리> · 크레딧 잔여 추정 $<2자리>` (흐린 색)
  - `export class MultilineBuffer { push(line: string): string | undefined; reset(): void; get isCollecting(): boolean }` — 줄 끝이 `\`이면 `\`를 뺀 줄을 모으고 undefined, 아니면 모은 줄과 합쳐 `\n`으로 이어 돌려준다.
  - `createPlainUi`의 `io`에 `historyFile?: string` 추가. 시작 시 읽어 readline `history`로 넘기고(최신이 앞), `history` 이벤트마다 최대 500줄로 저장.
  - `run(session, options: { commandContext: CommandContext; recordUsage: (costUsd: number) => Promise<UsageSnapshot> })`

화면 동작:
- `line` → `MultilineBuffer.push` → 완성된 입력이면 `parseInput` → command면 `runCommand`, prompt면 `session.send`.
- 모으는 중에는 프롬프트를 `… `로 바꾼다. Ctrl+C면 `reset()` 후 `> `로 돌아간다(종료 확인보다 먼저 처리).
- `turn_result` → `recordUsage(costUsd)` 후 `formatStatusLine` 한 줄 출력.

- [ ] **Step 1: 실패하는 테스트** — `MultilineBuffer`: `"a\\"` → undefined·isCollecting, `"b"` → `"a\nb"`; `"x"` → `"x"`; `reset` 후 isCollecting false. `formatStatusLine`: `{ model: "m", sessionCostUsd: 0.0123, remainingCreditUsd: 99.5 }` → `m · 세션 $0.0123 · 크레딧 잔여 추정 $99.50` 포함; model 없음 → `기본 모델`. 기록 파일: 임시 파일에 두 줄을 넣고 UI를 만든 뒤 PassThrough로 새 줄 입력 → 파일 첫 줄이 새 입력.
- [ ] **Step 2: 실패 확인** — `npx vitest run test/ui-plain.test.ts` → FAIL
- [ ] **Step 3: 구현** — `main.ts`에서 `configDir()` 기준으로 `historyFile`, `recordUsage = (cost) => addUsage(cost)`, `commandContext`를 만든다.
- [ ] **Step 4: 통과 확인** — `npm test && npm run typecheck && npm run build` → PASS

- [ ] **Step 6: Commit** — `feat: 명령·상태 줄·여러 줄 입력·입력 기록을 화면에 연결`
